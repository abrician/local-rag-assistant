Train, validation и test: зачем разделять наблюдения

Модель должна работать на примерах, которых не видела во время обучения. Train используют для подбора весов; validation — для выбора гиперпараметров и момента остановки; test — для итоговой оценки после выбора модели. Если подбирать параметры по test, он перестаёт быть честной проверкой: это утечка информации.

При классификации редких событий можно сохранять доли классов через stratify. Случайное зерно (random_state) помогает повторить разбиение, но само по себе не исключает утечку. Связанные записи одного клиента или соседние моменты временного ряда иногда нельзя случайно разносить по разным выборкам.

from sklearn.model_selection import train_test_split

features = [[i] for i in range(20)]
labels = [i % 2 for i in range(20)]
X_train, X_test, y_train, y_test = train_test_split(
    features, labels, test_size=0.25, stratify=labels, random_state=7
)
print(len(X_train), len(X_test))

Кросс-валидация повторяет обучение на нескольких разбиениях train-части и помогает оценить устойчивость выбора. Финальную test-часть при этом не используют для настройки.
